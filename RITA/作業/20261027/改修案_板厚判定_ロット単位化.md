# 改修案: 板厚判定を「釜単位」から「ロット単位」へ(論点6)

- 作成日: 2026-10-27 / 状態: 案(コードの読解に基づく。画面での再現は未確認)
- 出典: 2026/10/15 定例会の論点6、`TLN_M_GENERAL_ITEM_OPTN`(DB)、`REPOSITORY\20260910_ITAATU`(AP)

## 現象
板厚判定でNGが出ると、釜単位でエラーになる。ロット単位でエラーが出るようにしたい。

## 原因(コード上の根拠)
対象機能は `NIPPO_INPUT_08`(穴明け作業)。`SEARCH_AFTER` の `itatsu()` が板厚判定を行う。

1. 入力ロット(`2_LOT_NO`)から、`NIPPO_INPUT_06_LIST` のSQLで **PID(プレス構成=釜)** を1件取得する。
2. `NIPPO_INPUT_06_REPORT`(seq=1)のSQLを、そのPIDで実行する。このSQLは **PIDに属する全ロット分**(ロットごとに最新ID)を返す。
3. 返った全行を順に見て、`AUTO_090 == 1 && GIJUTU_090 != 0` の行が **1行でもあれば** `板厚判定がNGでした` を出す。

→ 判定のループが、入力ロットで絞り込まれていない。同じ釜の別ロットがNGだと、全ロットの入力が止まる。

## 改修案(最小変更)
ループの中で、入力ロットの行だけを判定対象にする。

```diff
 for(var i = 0;i < itemSelectList.length;i++){
   var lineDataMap = itemSelectList[i];
+  if(lineDataMap['LOT_NO'] != LOT_NO) continue;   // 入力ロットのみ判定する
   if(lineDataMap['AUTO_090'] == 1 && lineDataMap['GIJUTU_090'] != 0){
     TALON.addErrorMsg('板厚判定がNGでした');
     break;
   }
 }
```

- 修正箇所: `TLN_M_GENERAL_ITEM_OPTN`(FUNC_ID=`NIPPO_INPUT_08`、COL_NAME=`SEARCH_AFTER`、FUNC_KBN=`JAVA_SCRIPT_ENGINE`)のスクリプト本文。
- メッセージ文言は変えない。画面側のJS(`LOAD`)が、`板厚判定がNGでした(CMN_E0094)` という文言で、入力欄の無効化を判定しているため。
- 反映は、過去のリリースと同じく、`REPOSITORY` にリリース用フォルダ(`yyyymmdd_名称`)を作り、`TLN_M_GENERAL_ITEM_OPTN` のCSVを置く形が想定される(手順は要確認)。

## 要確認事項
- `GIJUTU_090 != 0` の意味(0=技術部確認OK、など)。
- `AUTO_091`(板厚2)の判定は、現行コードでは見ていない。今回の対象にするか。
- 1ロットが複数のPIDに属する場合がある(現行は先頭の1件のみ使用)。実データで該当があるか。
- `NIPPO_INPUT_08_TEST`(複製機能)にも同様のコードがある。反映の要否。
- 同じ判定が、他の日報機能(穴明け以外)にもあるか。
- 本番での検証方法(検証環境がない)。反映前のバックアップと、テスト対象ロットの選定。
